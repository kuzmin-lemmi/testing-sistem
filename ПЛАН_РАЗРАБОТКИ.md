# План разработки: система тестирования + LocalShot

Дата: 29.09.2026. Ветка: `localshot-link`.

## Цель

Система тестирования остаётся такой, как есть, со всеми возможностями. LocalShot нужен только для того, чтобы быстро собрать вариант из скриншотов. Между программами связь через **файл варианта**.

## Как это работает

1. **LocalShot** (дома или в школе): скриншот → ответ → задание в варианте. Вариант сохраняется одним файлом `Урок 29.09.variant`.
2. Файл переносится через Яндекс Диск, флешку или почту.
3. **Система тестирования**: «Загрузить вариант из LocalShot» → появляется обычный вариант.
4. Тестирование запускается как всегда: время, код доступа, калькулятор, Python, пауза, мониторинг, результаты, оценки, выгрузка.

Внутри системы тестирования ничего не меняется. Добавляется только новый способ получить вариант.

## Этапы

### Этап 1. Загрузка файла `.variant` в систему тестирования

Главный этап: после него связка уже работает.

- На странице **«Варианты»** появляется кнопка **«📥 Загрузить из LocalShot»**. Можно выбрать файл или перетащить его в окно.
- После загрузки появляется вариант:
  - название как у файла («Урок 29.09»);
  - задания в том же порядке, что в LocalShot;
  - ответы: одно поле, несколько полей или «несколько строк» (как в №25, 27);
  - файлы к заданиям прикреплены, ученик скачивает их как обычно.
- Задания попадают в банк, в раздел **«Общий банк»**: LocalShot не знает номер задания ЕГЭ.
- Если файл повреждён или это не вариант, выводится понятное сообщение, и **ничего не создаётся**, даже частично.
- Если вариант с таким названием уже есть, новый получит имя «Урок 29.09 (2)». Старый вариант не трогается.
- Ограничения увеличиваются только для этой загрузки: картинка до 30 МБ (весь экран на большом мониторе больше 5 МБ), файл варианта до 200 МБ.
- Автоматические тесты на загрузку: обычный вариант, несколько ответов, несколько строк, файл к заданию, повреждённый файл, повтор названия.

**Результат:** вариант из LocalShot можно запускать как обычное тестирование.

Что сделано сверх плана:
- Для заданий из «Общего банка» нигде не показывается «№1 ЕГЭ» (страница ученика, результаты, вариант, CSV): у них нет номера ЕГЭ.
- Файл к заданию скачивается под своим настоящим именем («Данные 17.txt»), а не под случайным набором букв.
- Система принимает файлы к заданию `odt, docx, pdf, py, zip` (кроме прежних `txt, csv, xlsx, xls, ods`).
- В `config.py` есть переменная `EGE_DATA_DIR` (папка данных): нужна автоматическим тестам, чтобы они не трогали рабочую базу.
- Запуск тестов из корня проекта: `python -m unittest discover -s tests -v`.

### Этап 2. LocalShot: только сборка варианта

- Из LocalShot убираются «Начать урок», «Результаты уроков», «Создать ярлык для учеников» и сервер для учеников. Код остаётся в истории git (ветка `variants-lesson`).
- Остаются скриншоты, редактор, «В вариант», окно варианта: порядок, правка ответов, переименование.
- При выборе файла к заданию можно выбрать только типы, которые принимает система тестирования (список в «Открытых вопросах»).
- В окне варианта появляется подсказка: «Загрузите этот файл в систему тестирования: Варианты → Загрузить из LocalShot». Рядом кнопка «Показать файл в проводнике».
- Работа идёт в новой ветке LocalShot, созданной от `variants-lesson`.

**Результат:** в LocalShot одна понятная задача — собрать вариант. Две системы тестирования больше не путаются.

### Этап 3. Ярлык ученика с ожиданием

Сейчас ярлык ведёт на `http://IP:8080/test`. Если система на компьютере учителя ещё не запущена, у ученика ошибка браузера, и страницу нужно обновлять руками.

- В панели учителя появляется кнопка **«Ярлык для учеников»**. Она сохраняет файл `Тестирование.html`, который один раз копируется на рабочие столы учеников. Это готовый кусок из LocalShot.
- Ярлык ищет компьютер учителя сначала по **имени**, потом по IP-адресам и показывает «Подождите». Когда система запущена, ярлык сам открывает страницу входа.
- Существующая страница «Тестирование не запущено» остаётся как есть.

**Результат:** ученик в любой момент открывает ярлык и ждёт, ничего не нажимая.

Как сделано:
- Кнопка **«💾 Скачать «Тестирование.html»»** на главной странице учителя. Рядом список адресов, по которым ярлык ищет компьютер учителя.
- Ярлык — один самостоятельный файл, ничего не загружает из интернета и из системы. Проверяет все адреса одновременно и переходит на `/test`, как только любой ответил. Если система долго не отвечает, показывает ученику проверяемые адреса.
- Для проверки в системе есть адрес `/test/alive` (открыт для всех компьютеров сети, как и остальные страницы ученика).
- Адрес на главной странице учителя теперь определяется и в школьной сети без интернета (раньше там мог показаться `127.0.0.1`).

### Этап 4. Варианты LocalShot прямо в системе

Чтобы не искать файл вручную:

- На странице загрузки показывается список файлов `.variant` из папки вариантов LocalShot: название, число заданий, дата. Это может быть папка на Яндекс Диске.
- Кнопка «Загрузить» у каждого. Уже загруженные помечены.
- Папка задаётся в «Настройках». По умолчанию: `Документы\LocalShot\Варианты`.

**Результат:** вариант, собранный дома, в школе загружается одним щелчком.

### Этап 5. Проверка в школе и инструкция

- Проверка на двух компьютерах: учителя и ученика. Брандмауэр Windows, ярлык, вход, ответы, результаты.
- Короткий раздел в `ИНСТРУКЦИЯ.md` и `ПАМЯТКА.md`: «дома в LocalShot → в школе в системе тестирования».

### Этап 3а. Ученик ничего не обновляет; вход без кода

- Страницы ученика (`static/js/student_watch.js`, адрес `/test/state`) сами следят за сервером:
  - «Тестирование не запущено» → сама открывает форму входа через 2–3 секунды после запуска;
  - форма входа → обновляется, если тестирование завершили или запустили другое;
  - страница результата → сама уходит на вход, когда учитель запустил новое тестирование.
  Во время самого теста работает прежняя проверка: когда учитель завершает тестирование, у ученика откроется результат.
- Вход по коду убран из интерфейса: при запуске тестирования нет галочки «Требовать код», у ученика нет поля кода. В системе возможность осталась (создание кода, проверка при входе, показ кода учителю). Вернуть галочку: переменная окружения `EGE_ACCESS_CODE=1` (или `SHOW_ACCESS_CODE_OPTION` в `config.py`).

## Потом (по желанию)

- **Номер ЕГЭ в LocalShot.** Если указать номер при добавлении задания, оно попадёт в свой раздел банка и сможет участвовать в тематических и случайных вариантах.
- **«Ученик сдаёт файл»** (как задания с загрузкой .ods/.odt) прямо из LocalShot.
- **Дробные числа в ответах.** Сейчас система считает `3,5` и `3.5` разными ответами, LocalShot — одинаковыми. Можно сделать одинаково.
- **Безопасность** (из разбора старой системы):
  - Python ученика выполняется на компьютере учителя. Лучше выполнять только в браузере ученика (Pyodide уже есть).
  - Стандартный секретный ключ: создавать свой при первом запуске.
- **Сборка системы в EXE**, чтобы в школе не нужно было ставить Python.

## Важно помнить

- Файл `.variant` содержит правильные ответы. Не кладите его туда, откуда ученики могут его взять.
- База системы (`data/database.db`) у каждого компьютера своя. Между домом и школой переносится только файл варианта.
- Файлы `10.odt, 17.txt, 3.ods, 9.ods` в корне папки не добавлены в git: похоже, это пробные файлы.
- После каждого этапа учитель проверяет результат сам.
