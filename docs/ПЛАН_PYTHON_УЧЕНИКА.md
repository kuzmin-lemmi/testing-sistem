Этапы 1–2 сделаны: на странице теста в программе ученика под заданием есть редактор, кнопки и вывод

## Протокол (уже зафиксирован страницей)

Страница → программа: `window.ipc.postMessage('py:' + JSON)`

| Сообщение | Когда | Что делает программа |
|---|---|---|
| `{type:'hello'}` | загрузка страницы теста | ищет Python, отвечает `ready({version})` или `missing()` |
| `{type:'run', run, task, code, file}` | «Запустить», F5 | готовит папку, скачивает файл задания, запускает код |
| `{type:'stdin', run, text}` | ученик ввёл строку для `input()` | пишет `text + "\n"` в stdin процесса |
| `{type:'stop', run}` | «Остановить» | убивает процесс со всеми потомками |

`file` — `{url, name}` или `null`; `url` вида `/attachments/<хэш>.txt`, отдаётся без входа (`system.serve_attachment`).

Программа → страница: `evaluate_script` с вызовами

- `window.studentPython.ready({version: '3.12.7'})` / `window.studentPython.missing()`
- `window.studentPython.output(run, 'out' | 'err', text)` — кусками, по мере вывода
- `window.studentPython.exit(run, {code, seconds, reason, message?})`, `reason`: `done` | `stopped` | `timeout` | `failed`

Страница сама не даёт запустить второй раз, пока идёт первый, и игнорирует сообщения чужого `run`.

## Что сделать

Новый модуль `student_app/src/python.rs`, в `main.rs` — только разбор `py:` в `ipc_handler` и новое событие.

1. **Событие `UserEvent::Script(String)`.** `webview` живёт только в потоке окна: потоки запуска присылают
   готовый скрипт событием, цикл событий вызывает `evaluate_script`.
2. **Строки в JS — через JSON.** Нынешний `js_string` не экранирует `\r`, `\t`, U+2028/2029 и прочие управляющие
   символы, а вывод Python на Windows идёт с `\r\n` — скрипт сломается. Нужна своя функция `json_string`
   (serde не обязателен: экранировать `"`, `\\`, всё `< 0x20`, U+2028/2029, `<`) и такой же разбор входящего JSON —
   в сообщениях всего 4 вида полей (строка, число, `null`, объект `file`), хватит маленького парсера или `serde_json`.
3. **Поиск Python** (один раз, ответ кешируется):
   1. `py -3 -c "import sys; print(sys.executable)"` — лаунчер находит установленную версию;
   2. `HKCU` и `HKLM\Software\Python\PythonCore\*\InstallPath` — `ExecutablePath` или `<путь>\python.exe`;
   3. `python.exe` из `PATH`, **кроме** `%LOCALAPPDATA%\Microsoft\WindowsApps` — там заглушка Microsoft Store,
      которая открывает магазин (либо псевдоним нового Python Install Manager — его проверяем запуском `--version`
      с таймаутом).
   Версию — из `sys.version`. В `allowed.txt` уже есть `python.exe`, но это про окна, а не про запуск.
4. **Запуск.**
   - Папка `%LOCALAPPDATA%\Тестирование\python\<task>\`; перед запуском очистить, положить файл задания
     под его настоящим именем (`file.name`, только `basename`) — ученик пишет `open('17.txt')`.
   - Скачивание файла — `origin + url`, двоичный ответ без ограничения 64 КБ (у `http_get` в `server.rs`
     ограничение и `String`; нужен отдельный `http_download` в файл). Кешировать: файл не меняется за тест.
   - Код — в `solution.py` (UTF-8 без BOM), запуск `python -u -X utf8 solution.py`, `PYTHONIOENCODING=utf-8`,
     `cwd` — папка задания, `CREATE_NO_WINDOW` (иначе на столе теста мигнёт консоль).
   - Процесс — в **Job Object** с `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`: «Остановить», таймаут и выход из
     программы убивают и дочерние процессы (`multiprocessing`, `os.system`). Нужна фича
     `Win32_System_JobObjects` в `windows-sys`.
   - stdout и stderr читают два потока; вывод копится и уходит странице не чаще раза в ~50 мс
     (цикл `print` не должен заваливать окно тысячами `evaluate_script`). Предел на программу — 200 000 символов,
     как у страницы; дальше — читать и выбрасывать, чтобы процесс не завис на полном канале.
   - Трассировку ошибки — как в IDLE: путь `solution.py` заменить на `<код задания>` или убрать
     (`File "...\solution.py", line 3` → `line 3`).
5. **Остановка.** `stop` → `TerminateJobObject`, `exit(..., reason:'stopped')`. Таймаут → `reason:'timeout'`
   и `seconds`. Не удалось запустить → `reason:'failed'` с понятным `message`.
6. **Одна программа за раз.** Новый `run`, пока идёт старый, — убить старый (страница так не делает, но
   перезагрузка страницы может). Ушли со страницы теста (`/test/result`, выход) — убить.

## Решения, которые нужно принять

| Вопрос | Предложение |
|---|---|
| Сколько секунд даём программе | **30 с** — принято (у запуска на компьютере учителя — 10 с, для перебора в №25 мало). Время ожидания `input()` тоже входит |
| Ограничение памяти | **1 ГБ** на программу со всеми потомками (`JOB_OBJECT_LIMIT_JOB_MEMORY`) — принято |
| Python не найден | `missing()`, а в мониторинге учителя — отметка «нет Python» (по желанию, позже) |
| Что видит учитель | пока ничего: код ученика остаётся у него. Позже — код отправлять вместе с ответом |

## Как проверять

Сервер и программа на одном компьютере:

```
python server.py
cd student_app
cargo run -- --no-desktop --server 127.0.0.1
```

Отладочная сборка не устанавливается, `--no-desktop` — без своего рабочего стола, `STUDENT_APP_DEBUG=1` —
журнал в консоль. В системе учителя: тестирование с включённым Python и заданием с файлом.

Проверить: версия Python в статусе; `print`; ошибка (красным, номер строки); `input()`; бесконечный цикл и
«Остановить»; таймаут; `print` в цикле на миллион строк (окно не виснет); `open('файл.txt')` из задания;
русские буквы в коде и выводе; вывод с `\r`; `multiprocessing` — потомки убиты; компьютер без Python → `missing`.

Автотесты Rust (`cargo test`): `json_string`, разбор сообщений, очистка трассировки, поиск Python
с поддельными путями. На этом компьютере: Python 3.12 и 3.14 (`py -0p`), заглушка в `WindowsApps` —
хороший случай для проверки поиска.

Готово, когда: всё из списка проверено на этом компьютере, `cargo test` и `cargo clippy` чистые,
PR #2 снят с черновика. Потом — проверка на компьютере ученика в школе (свой рабочий стол, учётная запись
без прав администратора).
